# Writing a handoff

The next session starts with nothing but this note and what's written in the project. Write what
it needs to continue **exactly** where you are, and nothing it can read elsewhere.

## Include

- **Where you are:** what you're in the middle of, and the exact next step (a file, a command, a
  decision to make).
- **Decisions and why:** choices you made that aren't obvious from the work, and the ones you
  rejected, so they aren't made again.
- **What you learned that isn't written down:** gotchas, commands that work (and ones that don't),
  where things are, who or what you're waiting for.
- **Loose ends:** things started and not finished, programs you left running and how to start
  them again, temporary files.

## Leave out

- What the plan, the task, the glossary, the rules register or the project's documents already
  say. Point to them instead.
- The story of how you got here, unless it explains a decision.

## And

- If something you learned should outlive this handoff (a convention, a term, a rule), say where it
  belongs (documents, glossary, rules register) so it gets written there.
- Be specific: names, paths, numbers. A handoff that says "continue the work" is no handoff.
